## 摘要

谷歌OCS和NVIDIA Spectrum-X CPO代表了解决"AI数据中心的互联瓶颈"的两个截然不同的技术哲学。**OCS是"光域交换"——光信号始终是光，不走电；CPO是"光电紧耦合"——将光引擎压缩到ASIC封装内，通过缩短电学路径来改善信号。** 一个做减法（去掉O/E/O转换），一个做加法（把O/E做得更近更高效）。两套体系短期互补、长期有可能走向融合。

以下从技术路线、供应链、下游生态三个维度展开对比，并梳理两方共同供应商。

## 一、技术路线对比

### 核心架构哲学

| 维度 | 谷歌 OCS | NVIDIA Spectrum-X CPO |
|:---|:---|:---|
| **核心技术** | MEMS 3D光束偏转（微机电微镜阵列） | 硅光MRM（微环调制器）+ CPO共封装 |
| **光信号路径** | 全程光 — 无O/E/O转换 | 有O/E — 在ASIC封装内完成电光转换 |
| **交换粒度** | 电路级（光纤对光纤） | 包级（交换机ASIC + 光引擎内部处理） |
| **速率透明性** | ✅ 速率透明（800G→1.6T→3.2T无需换硬件） | ❌ 速率依赖（每次升级需改ASIC/光引擎） |
| **功耗特征** | 与端口数相关、与速率无关 | 与速率强相关（SerDes功耗随速率指数增长） |
| **部署状态** | 已在TPUv4~v7生产部署（~2021起） | 2026 H2开始sample，2027大规模量产 |
| **适用场景** | Scale-Out（主）+ Scale-Up（探索） | Scale-Up（主）+ Scale-Out（过渡期） |
| **可维护性** | 无源设备，寿命>10年 | 有源封装，光引擎维修需整机更换 |
| **复用X代速率** | 可跨代 | 需同步升级 |

### 两种架构的系统级定位

```

│    ├── 内部互联: PCB/铜线 (电)                         │
│    └── 外部互联: 96路光缆 → Palomar OCS (MEMS光反射)    │
│                        ↑  纯物理层，0 O/E/O             │
│  48台 OCS units (144×144 ports each)                   │
│   = 全部光缆→48台OCS→目标光缆 (无中间电交换)            │
│  OCS = 巨型物理层光纤配线架                             │
└───────────────────────────────────────────────────────┘

NVIDIA Vera Rubin + Spectrum-X CPO
┌───────────────────────────────────────────────────────┐
│  GPU ↔ NVSwitch (铜缆/NVLink)                         │
│       ↓                                               │
│  Spectrum-X CPO 交换机                                │
│    ├── 交换ASIC (NVIDIA自研)  ← 电核心                  │
│    ├── 硅光引擎 (TSMC COUPE, MRM@200G/ch)             │
│    │    └── 外部激光源(ELS) → 注入CW光                   │
│    └── 光纤/连接器 → 下一跳                              │
│  CPO = 把光引擎嵌入ASIC封装 = 集成式电光转换              │
└───────────────────────────────────────────────────────┘
```

### 技术优劣势对比

| 优势 | 谷歌 OCS | NVIDIA CPO | 关键判断 |
|:---|:---:|:---:|:---|
| **功耗（10万卡集群）** | ★★★★★ | ★★★★☆ | OCS全光直通无电力消耗，CPO节省~70%比可插拔但仍有ASIC功耗 |
| **延迟** | ★★★★★ | ★★★★☆ | OCS仅光子传播时延(纳秒级)，CPO含SerDes+光引擎延迟 |
| **带宽密度** | ★★★☆☆ | ★★★★★ | CPO将光引擎集成封装内，IO密度远超OCS |

| **高研发/量产壁垒** | ★★★☆☆ | ★★★★★ | OCS的MEMS已成熟；CPO良率/热管理/封装仍在爬坡 |

### 互为补充还是互为竞争？

**目前格局：互补>竞争。**

国盛证券2026年4月研报明确指出：OCS和CPO不是替代关系，而是协同融合。OCP白皮书（2026年4月发布，由Google/Lumentum/Ciena等联合撰写）进一步确认：OCS在Scale-Out和集群重构中具备不可替代性，CPO主要承担Scale-Up的高密度互联。

本质区别：
- OCS解决的是**拓扑灵活性和光路直达**（数据中心/集群级的连接）
- CPO解决的是**芯片I/O瓶颈和功耗**（机柜/芯片封装的连接）

```mermaid
                    ┌─────────────────┐
                    │  AI 数据中心     │
                    │  互联需求        │
                    └──────┬──────────┘
                           │
            ┌──────────────┴──────────────┐
            ▼                              ▼
    ┌──────────────┐            ┌──────────────────┐
    │ Scale-Out    │            │ Scale-Up         │
    │ (机柜间/走廊) │            │ (机柜内/芯片间)    │
    │              │            │                  │
    │ 谷歌 OCS ✅  │            │ NVIDIA CPO ✅   │
    │ NVIDIA探索中 │            │ 谷歌下一代        │
    └──────────────┘            └──────────────────┘
```

值得注意的是**NVIDIA也已在布局OCS**。2026年OFC上，NVIDIA Feynman架构（计划2028年）将OCS纳入下一代网络方案，目标实现芯片级OCS集成（来源：国盛证券2026-04-06研报）。这说明两巨头的技术路线正在**双向趋近**：NVIDIA从CPO向OCS延伸（从片上集成走向全光交换），谷歌从OCS向CPO延伸（从全光交换走向片上集成）。

## 三、下游生态对比

### 3.1 生态规模与成熟度

| 维度 | 谷歌 OCS | NVIDIA CPO |
|:---|:---|:---|
| **已部署规模** | TPUv4~v7集群，数千台OCS在网 | Sample阶段，尚未大规模部署 |

| **供应商生态** | 成熟（1家自用+多家供应商） | 建立中（TSMC绑定+双重激光器供应商） |
| **下游客户** | 谷歌自用为主（少量供Salesforce/Anthropic） | 全行业（云厂商+企业AI） |
| **开放程度** | OCP开放（开源SDN、gNMI接口） | 封闭（NVIDIA全栈集成） |

### 3.2 NVIDIA的生态策略

NVIDIA的策略更激进——通过**资金绑定+全栈控制**重建光互联链条：
- 2026年3月宣布向**Lumentum**和**Coherent**各投资$2B（合计$4B），附带数十亿美元采购承诺
- Jensen Huang原话：“Together with Lumentum, NVIDIA is advancing the world's most sophisticated silicon photonics”（来源：CNBC, 2026-03-02; NVIDIA官方新闻）
- 核心目的：将光学供应链从"外购"变为"战略控制"——复制其在HBM/先进封装上的success
- 分析师判断：NVIDIA视**光学为下一战略瓶颈**，如同一两年前对HBM的掌控（来源：Futurum Group分析）

### 3.3 谷歌的生态策略

谷歌的策略是**自研+开源化推动**：
- 系统完全自研（TPU+OCS+Orion SDN+JAX/XLA全栈）
- 但光模块/光器件层面采用开放供应商框架（中际旭创/Coherent/光迅/德科立多家供应）
- 正通过OCP OCS子项目推动标准化，目标是使OCS成为AI数据中心的**行业标准基础设施**

## 五、对159682/159632持仓影响

### 5.1 两套技术路线对历史分析框架的修正

上一轮分析我判断"NVIDIA Spectrum-X CPO对中际旭创/新易盛不是威胁"。现在加入谷歌OCS的视角后，需要补充一个重要发现：

**双引擎供应商的上行确定性被强化。** 谷歌OCS和NVIDIA CPO的技术路线虽然不同，但都**增加而非减少了对光模块/光器件的总需求**——因为：
1. **谷歌OCS需要大量定制光模块**连在OCS两端（每台OCS ~144对光纤 = 288个光端口）
2. **NVIDIA CPO需要配套光模块**进入Scale-Out网络（CPO只在Scale-Up使用）
3. **两套体系对高端器件（FAU/MPO/ELS/光引擎封装）的需求叠加**

证券时报2026-05-29调查的核心结论也支持这一点：**"2026至2027年的网络规划仍以可插拔方案为核心，并未有任何云厂商计划在近两三年内大规模部署CPO。"**（来源：多家上市公司与主要云服务商沟通确认，证券时报）
